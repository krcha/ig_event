# Event and venue structured data audit

Audit date: 2026-10-17. Scope: public event detail and venue detail pages,
especially event timestamps and weekly venue hours.

Status: local implementation and focused SEO QA complete. Production deployment
and public verification are pending; use the subsequent production receipt for
deployment evidence. This report does not claim Google Rich Results Test or
Search Console validation.

## Detection and findings

The four representative production URLs below each returned two parseable,
server-rendered JSON-LD blocks: Event or LocalBusiness, plus BreadcrumbList.
No Microdata `itemscope` or RDFa `typeof` attributes were detected in those pages.

| Page/schema | Before | Local implementation |
| --- | --- | --- |
| Dim Event: Stellarcompanion | Date-only start; no end or place hours | Keeps date-only start and no end; adds seven sourced weekly opening periods to its Place |
| Dim venue: LocalBusiness | No openingHoursSpecification and no visible weekly hours | Adds the same seven periods and a visible Hours section |
| Muzej 90ih Event: JESENJE KUVANJE JAM-a | Confirmed 17:00 start; no end or place hours | Keeps confirmed start and no Event end; adds seven venue opening periods to its Place |
| Vrtoglavica Event: Chillout Zone | Confirmed 23:00-05:00 overnight Event range | Preserves the next-day end and adds six venue opening periods to its Place |

The existing event timestamps in these examples were correct. Missing weekly
business hours were the main schema gap. Venue hours are now attached to the
place rather than used to invent event timestamps.

## Timestamp and hours rules

- A known event start uses its announced local clock and Europe/Belgrade offset.
  An explicit event range can supply endDate, including the following day.
- An unknown or inferred event time remains date-only. A start-only event's
  assumed venue closing remains a presentation/filtering rule and is not an
  announced Event endDate.
- Invalid calendar dates omit Event schema. Spring DST gaps and repeated autumn
  clocks avoid inventing an exact instant or an ambiguous closing date.
- Sourced weekly hours use OpeningHoursSpecification on LocalBusiness and the
  Event location Place. Overnight periods retain their opening weekday; multiple
  periods, known closed days and 24-hour periods use the appropriate conventions.
- Missing days stay unknown. Invalid schedules, conflicting weekdays, source
  mismatches and non-Belgrade timezones omit hours. A known previous-night period
  must not also be marked closed for the entire following day.

  sourced weekly periods and preserves the three expected event timestamp cases.
- Full release QA and production checks are recorded separately during release.

## Data limits

Missing hours and map coordinates require source research; schema must not fill
them with guesses. Some verified sample venues also lack detailed street
addresses, so their current PostalAddress contains only the known locality and
country. Unknown venue hours remain omitted. The requested venue-gap exports
provide follow-up lists for missing coordinates and hours.

This audit does not promise a Google rich result, indexing or eligibility in
every region. It does not add ticket offers, reviews or other facts unsupported
by the public source data.
